一、执行摘要

受管平板的 MDM 浏览器过滤器以「无效的响应」软拦内网裸 IP 访问。两轮共 62 个探针的黑盒测绘将引擎判定规则完整收敛（模型 v1→v6），核心结论：

引擎最终模型（v6）：对 GURL 规范化后的 URL authority 拆为 token（@ 前）与 host 两段——token 非空时只查 token（含黑名单 IP 点分四段子串即拦，host 完全不被查）；token 空或无时才查 host。黑名单 = {192.168.40.1, 192.168.40.90, 192.168.125.1}，全端口、纯字符串子串匹配、大小写不敏感。32 个数据点零矛盾。

判读规则（本轮方法论核心）

  • 「无效的响应」（秒出）= 引擎软拦——合成响应，目标侧零痕迹；顶层导航与 XHR onerror 均属此列。
  • 「连接被拒绝」/ 超时 / 出任何页面 = 引擎放行——网络层真实结果。私网不可达目标转圈 30 秒以上，转圈本身就是放行证据。
  • 每轮带阴性对照（DN1 随机串）；服务端 beacon 落账为准，屏幕文案只作旁证。
两台设备、两个内核（X5/89 与系统/80）全部结论一致 → 引擎位于 WebView 之下的 MDM 层，与内核无关。

三、引擎判定规则终稿（v6）

BLACKLIST = {"192.168.40.1", "192.168.40.90", "192.168.125.1"}   # 纯子串匹配，全端口

def decide(authority: str) -> bool:
    # authority = GURL 规范化后的 "userinfo@host:port"（凭据未剥离）
    if authority.count("@") >= 2:
        return DENY                                        # N6：粗糙合法性检查

    token, _, hostport = authority.partition("@")

    if token == "":                                        # 空/无 userinfo → 查 host
        host = strip_port(hostport)
        return DENY if any(ip in host for ip in BLACKLIST) else ALLOW

    return DENY if any(ip in token for ip in BLACKLIST) else ALLOW
    # token 非空 → 只查 token，host 完全不被查（userinfo 旁路的真正机理）

九、网络侧第二层观测

  • 域名形态（无 quad）导航全部出网成功（DN2–6、DN12、DP8 随机新域名）→ 第二层「域名白名单+默认拒绝」对浏览器会话内的新域名未设防，或其白名单按 SNI/Host 匹配且动态学习在吸收。
  • 热点对照（192.168.137.x 不受管网）全功能 → 管控面只在 40 网生效。
  • 成因未定，是本次唯一未收敛的外层未知；B 方案稳定性与此相关（已有数日稳定实测窗口）。
