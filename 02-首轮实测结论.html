1引擎模型 v2 —— 六条定论

编号定论置信度关键证据
E1判定点在 WebView 请求拦截层,看到的是「凭据剥离之前」的原始 URL高S2(XHR userinfo):页内 200,服务器日志唯一一条干净 /api/ping 200(12:54:35.774);S1(干净 XHR):页内 OK 404 但服务器零命中 → 同一条线路,判定差异只能来自剥离前的字符串
E2匹配对象是 authority 段(userinfo@host:port):大小写不敏感、与端口无关;query/fragment 不参与高N3 经 18081 放行(12:53:33 命中);N7 全大写放行(12:53:41);N4(query 含域名)/N5(fragment 含域名)被拦且零日志
E3拦截表现是「合成 404」软拦(子资源)/「无效的响应」拦截页(顶层导航),不是丢包高S1 页内 OK 404 + 服务器零日志;顶层直接访问 40.90:9011 出「无效的响应」(操作者确认)
E4放行后凭据被剥离:线上请求均为干净形式;文档 URL 显示为剥离后形态高D 组页「进入 URL」显示干净 http://192.168.40.90:9011/ab.html?mode=A,但该请求实为 userinfo 基址解析出的相对链(12:54:46 命中)——显示已归一化
E5协议面:fetch 对 userinfo 规范期抛错;XHR 剥离后照发;img/script 剥离→拦;明文 WS 带 userinfo 直达服务器高S3 TypeError: Request cannot be constructed…;S2 200;S4/S5 ERR 且零日志;S7 OK open + 12:54:35.813 WS-UPGRADE /ws 来自 40.27
E6大文档不是问题:8MB 页面在 40 网正常加载中高12:55:02 ab.html?mode=A&pad=8 命中 + 截屏正常渲染 → 13.7MB「渲染崩溃」假说不再需要
一句话模型:过滤器 = 「对 WebView 每个请求的 authority 原始字符串做大小写不敏感的包含匹配;命中 → 剥离凭据放行;不命中 → 合成 404 / 拦截页」。无 CIDR、无端口语义、不看 query/fragment、不做 host 解析。

2基线文档 §四悬案定案(B5 关闭)

历史矛盾「11:05-11:07 全通 vs 11:23+ 全拦」不需要「策略同步窗口/非确定性」假说,机制上必然:

历史现象v2 模型解释
11:05-11:07 @ 内联页全通(icons/app-control/ai-chat 全 200)页面与其全部子资源都以 userinfo 形态构造 → authority 全部命中 → 全放行(E1/E4)
11:23+ 之后 HTML-only、零子资源回退版本引入「干净 base / 干净子资源 URL」→ 逐请求 authority 不命中 → 合成 404 软拦(E3),服务器侧表现为「零请求到达」,与当时观察一致
fetch 崩溃(ai-chat stream)userinfo 基址下任何 fetch(含相对路径)构造期抛错(E5)→ 与当时 /api/ai-chat/chat/stream 失败吻合

结论:引擎是确定性的;方案 §7 的严格 5×60s A/B 降级为「可选复验」,不再阻塞结论。

4本轮两个「假阴性」通道(方法论修正)

  • observe 回传丢失:40 网会话里页内回传用 fetch(相对路径) → 在 userinfo 基址下构造期抛错(E5)→ .catch 吞掉 → D 组与手点「被拦」的上报全部没到服务器。修正:回传改用 XHR(no-cors)。
  • XHR 内存缓存:S6/P1 的 200 没有产生第二条线上请求(同 URL 复用 S2 缓存)。修正:探测 URL 加随机 ?r= 防缓存。
  • 热点对照的局限:热点会话(137.247)顶层导航可经 hairpin 到达(日志源地址显示 40.90),但热点源页面发往 40.90 的 XHR/img 未达(路由/防火墙行为,非过滤器);后续热点对照统一用 http://192.168.137.1:9011 访问本服务器。

6对 CI 适配与漏洞报告的含义

临时适配(自有服务可用形态,依 E1-E5)

  • 入口:userinfo 形态导航(或已放行页内相对链);
  • 资源:全部走「相对路径」(解析后继承 userinfo authority,逐请求命中)或内联 dataURI;
  • API/长连接:URL 字符串必须带 userinfo authority(XHR 自动剥离、WS 直达),禁用 fetch(规范抛错)——即文档 §五假设的实测修正版;
  • 限制:页面显示 URL 已被归一化(E4),刷新/分享链接时需重新拼 userinfo 形态。

厂商漏洞报告证据链(已完备)

  • ① 判定基于原始 authority 字符串而非解析后 host(E1/E2);
  • ② userinfo 可过判定、放行后凭据剥离(E1/E4),纯客户端无通用利用面但管理语义被完全绕过;
  • ③ 拦截为合成 404 软拦,不产生网络侧审计痕迹(E3);
  • ④ 大小写/端口不敏感、query/fragment 与 CIDR 均不参与(E2、基线 §10.1);
  • ⑤ 明文 WS 同样仅字符串判定(E5)。
边界不变:以上结论仅用于授权环境内的学习与自有配置自查;不做持久化、不装载外部载荷、不触碰厂商云端与其它设备。
