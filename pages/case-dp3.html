D 组 · IP 守卫集形状测绘 v3

页面版本 v3(2026-09-09)。背景:DP17 证伪「IP 白名单默认拒」—— 公网 IP 119.6.237.1 被引擎放出内网(连接被拒=真实网络错误,非软拦)。本组测引擎到底守「哪个集合」的目的地。
本组判读规则(全部看屏幕,通用):出现『无效的响应』=引擎拦(点「被拦」);出现『连接被拒/超时/任何页面内容』=引擎放行(点「放行」)。私网不可达目标可能转圈 30 秒以上才报错,耐心等 —— 转圈本身就是放行证据。所有目标都不在本靶机上,不会有服务端日志,屏幕即真相。

D 组 · 守卫集形状(DP20-DP32)

编号动作探测点判读含义结果
DP20同 /24 相邻主机(无监听)拦=守卫覆盖整个 /24 网段;拒/超时=只精确守 .90 单个 IP未测
DP21192.168/16 其他子网拦=整个 192.168/16 在守卫集;否则=只看 /24 或精确名单未测
DP2210/8 私网段拦=10/8 在守卫集(RFC1918 全守);否则=守卫集更窄未测
DP23172.16/12 私网段拦=172.16/12 在守卫集;否则=守卫集更窄未测
DP24回环地址(平板自身)拦=loopback 也守;拒(应很快)=只守私网单播未测
DP25公网有真实监听者(Cloudflare)页面出内容=公网全通实锤;拒/超时=引擎放行但网络不通;『无效的响应』=公网也拦(推翻 DP17)未测
DP26DN7 复测(新语义) —— 网关 IP。当年判「拦」发生在两文案区分确立之前,可能把网络拒绝误读成引擎拦『无效的响应』=黑名单含 .1(多条目黑名单);拒/超时=黑名单仅 .90,DN7 拦结论作废未测
DP27网关 80 端口(可能有管理页)出页面/拒=引擎放行 .1(双重确认);『无效的响应』=同 DP26 拦侧未测
DP28siteList 另一个 /24 条目(192.168.125.0/24 课堂互动)的网络地址 —— 探黑名单来源拦=黑名单与策略 /24 条目相关(但须解释 DP17 为何放行 119.6.237.1);过=黑名单是独立配置的小集合未测
DP29黑名单 IP 作 token + 域名 host —— token 段是否也查黑名单过=黑名单只作用于 host 段(v4 预测);拦=任一段含黑名单 IP 即拦未测
DP30子串 vs 精确判别 —— "192.168.40.1" 是 "192.168.40.100" 的前缀『无效的响应』=黑名单按子串匹配(40.100 被 40.1 连坐);拒/超时=精确匹配 → 40.100 别名直访路线复活未测
DP31portal 认证地址(校园常用基础 IP)『无效的响应』=黑名单第四成员;出页面/拒/超时=黑名单仍仅三成员未测
DP32非域名单字符 token("a",无点)+黑名单 host —— token 短路的适用条件(v6 终验)到达本页(自动标绿)=任意非空 token 都短路;『无效的响应』=token 须域名样(含点)才短路未测
