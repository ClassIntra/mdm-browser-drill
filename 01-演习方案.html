MDM 管控下 · 浏览器层过滤行为全面测试演习

演习方案 v1.0  |  2026-09-08  |  基线依据:资料库文档《EBMD MDM 过滤器行为模型(实测知识与证据 2026-09-08)》 |  方法参考:github.com/AndrewAltimit/exploits(仅方法论)
范围:自有受管设备 192.168.40.27 ↔ 自有服务器 192.168.40.90 性质:受控授权审计 · 证据驱动 · 可回滚 目标:定案过滤器确定性 + 产出厂商漏洞证据链

0摘要与定位

本演习不是「帮助设备逃逸管控的作业指导」,而是对自有 MDM 部署的一次受控安全评估:通过浏览器形态学测试,验证 URL 过滤器引擎的真实判定规则,把基线文档中带置信度标注的行为模型升级为可复现、带证据的定论,并完成两件事——(1) 用 A/B 受控协议解决文档 §四「非确定性/策略同步窗口」这一未定案矛盾;(2) 产出可直接提交厂商的漏洞报告证据链(URL 字符串匹配 + userinfo 绕过 + CIDR 条目无效)。

为什么引用 AndrewAltimit/exploits:该仓库没有 MDM/URL 过滤专项(经核对其 README 与目录,相关的是浏览器扩展供应链、浏览器原生后利用、Chrome/Firefox CVE、SCCM/RMM/EDR 等,目标对象与本题不符)。它真正可迁移的是方法论与纪律:沙盒遏制(ContainmentGuard:强制回环/隔离,超出即拒)、攻击-检测成对交付(每个动作必配防御侧观测)、Mock 环境先行。本演习按同一纪律落地:隔离到 9011 演习端口、只碰自有地址、每个用例都带观测点与检测建议。

1授权声明与红线(先读)

演习合法性前提(必须全部满足,任一不满足即中止)

  • 资产归属:目标仅限自有受管设备 192.168.40.27 与自有服务器 192.168.40.90(本机);不触碰其它租户/班级设备、不直接攻击厂商云端 mdm 服务端(策略接口只能由设备自身按既定节奏拉取,演习不做任何重放/篡改/伪造)。
  • 人员授权:执行者为该 MDM 部署的 owner/受权审计人(与基线文档立场一致)。
  • 透明原则:全程保留服务器访问日志与设备侧观测,不做日志清理、进程伪装、审计规避。

红线(本演习明确排除,与既定运维安全边界一致)

排除项原因 / 替代
运行 / 编译 exploits 仓库内任何二进制、Rust crate、CVE 载荷、C2/窃密模块目标对象不符(面向桌面/云/EDR),且为武器化代码;本机不落地执行。方法层已足够。
浏览器引擎漏洞利用(CVE-2024-9680 / CVE-2026-2441 类)即使成功也只是代码执行,不改变网络白名单判定;属越权攻击面,且无补丁确认前不可用于生产设备。
持久化 / 自启动 / 刷机 / Root / Xposed / ADB 恢复与「不刷机、不动刀」约束冲突;会命中 blockapp 日检与 L4 违规锁。基线文档 §十四已逐条证伪。
ARP/DHCP 欺骗、TCP RST、DNS 劫持、策略包伪造过不了响应签名 + md5 转存前后校验;且属中间人攻击面。基线文档 §十四 1/3/4。
任何指向第三方/公网的「放行测试」演习只度量「40.90:9011 是否可达」这一布尔量;URL 里的域名串仅作为字符串样本,不解析不访问。
结果用于真实逃逸课堂管控演习结论仅用于授权环境内的学习与自有配置自查。
判定规则:所有用例的观测对象是「服务器是否收到请求 + 设备浏览器表现」,二者必须成对取证。任何单侧观察(只截屏、只看日志)不计为证据。

3基线行为模型(引用,含置信度)

#模型陈述置信度来源(文档节)
B1导航判定基于 URL 字符串,不基于解析后 host;裸 IP:PORT 被拦(即使 40.0/24 已在白名单单),字符串含已放行域名即放行高§二.1 / §10.1
B2子资源/API 按同一字符串规则逐请求判定;@ userinfo 形式可达,干净形式被拦高§二.2(日志)
B3fetch() 对带 userinfo URL 直接抛错(Request cannot be constructed…);XHR(axios)剥离 userinfo 后照常发;带 userinfo 可加载;图片等会剥离→变干净→被拦。实测引擎:腾讯 X5 WebView(Chromium 89 基线),fetch/XHR 的 userinfo 行为沿用 Blink 规范,可预期与基线文档一致,但须用 M 组逐条复核高§二.3(浏览器规范)+ 本演习 M 组
B4明文 WebSocket 曾有放行先例(noVNC);137 热点网段原生可用(含 AI 流式)中§二.4(日志)
B5过滤器存在非确定性 / 策略同步窗口的可能(11:05-11:07 全通 vs 11:23+ 全拦);可能被 13.7MB 文档崩溃掩盖中·未定案§二.5 / §四
B6策略接口响应带 md5+签名、内存缓存、00:01 定时拉取 → 篡改/伪造/断网 fail-open 均不可行高§十一 / §十四
B7设备强制面:ADB/USB 禁用、私有 DNS 禁、应用冻结、黑名单日检、定位采集;侧载/证书通道被封高§十一 / §十四
演习核心价值:把 B1–B4 从「当天特定时间线的观察」升级为「受控可复现结论」,并对 B5 做定案实验;B6/B7 不重测(已高置信)。

4仓库能力映射(采用 / 改编 / 排除)

仓库模块判定理由与本演习的用法
ContainmentGuard 遏制纪律采用演习强制「9011 独立端口 + 仅自有 IP + 不落生产」;访问越界地址的用例直接删除。
Attack ↔ Detection 成对交付采用每条用例带「服务器观测点 + 设备观测点 + 防御侧检测建议」(见 §8),直接复用其「进攻模块必有防御侧目录」的结构。
Mock 环境先行 / 分阶段迭代采用本机 curl/Node 先行验证演习页可服务、日志可写,再上真机;结果先本地收敛再打补做 A/B。
浏览器扩展供应链(MV3)攻击面排除受管设备无扩展安装通道(interfaceManager 收口),且属终端对抗而非网络过滤器评估。
浏览器原生后利用 / WASM 载荷 / 浏览器 CVE排除武器化且不改变白名单判定;违反红线。
Evasion(Rust:睡眠混淆/间接调用/ETW/AMSI)、BYOVD、EDR 静默排除面向 Windows 端点的对抗技术;与既定「透明运维、不做审计规避」边界冲突。
C2、凭据窃取、RMM 滥用、横向移动、云身份、Snowflake/Databricks 链排除目标对象不符,且属高危害攻击面。
结论先行:经映射,该仓库对本题的净贡献 = 方法论 3 条,载荷 0 条。浏览器层过滤的实测攻击面远小于仓库覆盖面——这正是值得写进演习报告的结论之一。

5演习总流程

  1. 准备(P0):本机启动演习服务器(见 README 启动节),curl 冒烟自检 9011;确认 9001 生产服务未受影响;设备接入 40 网段 WiFi。
  2. 基线复测(P1):真机执行 N 组(导航层)用例,重建文档 §三 关键时间线样本(约 20 分钟)。
  3. 子资源层(P2):真机打开 case-sub.html,页内自动探测 fetch/XHR/WS/img 的各类 URL 形态并回传,人工核对服务器日志。
  4. 确定性定案(P3):按 §7 A/B 受控协议执行,目标:B5 定案为「确定性」或「策略同步窗口」并测出窗口量级。
  5. 对照(P4):设备切 PC 热点 137.x 重跑 P1 代表性用例,区分过滤拦截与服务端故障。
  6. 收敛(P5):按 §9 判定规则收敛每条用例,补证据(截屏/日志节选),填记录表。
  7. 回滚(P6):停演习服务器;确认生产 9001 与设备状态无残留(文档 §七 基线核对)。
  8. 交付(P7):产出:演习记录表 + 厂商漏洞报告证据包(§8 检测建议并入)+ 管理端白名单工单建议。

6用例矩阵(分层)

执行约定:每条用例 = 设备浏览器动作 + 服务器日志命中情况 + 设备表现,三列证据。URL 中的 SVCDOM 指代放行名单中存在的域名字符串(如 service.example.com),LABIP=192.168.40.90,LABPORT=9011。所有目标均为本环境自有地址。

6.1 N 组 · 导航层(顶层导航)

编号导航 URL 形态假设(依模型)证据/判定
N1http://LABIP:LABPORT/ 裸 IP:PORT被拦(字符串无放行域名)→ 服务器无日志复现文档 §二.1
N2http://SVCDOM@LABIP:LABPORT/ userinfo放行(字符串含放行域名)→ 日志命中复现 11:05-11:07 形态

7A/B 受控协议(B5 定案)

目的:判定过滤器是确定性(同形态同结果)还是存在策略同步窗口(随策略拉取周期变化)。基线 §四 要求「同一分钟内 A/B 交替」。

  1. 轮次:连续 5 轮,每轮 60s:第 0-25s 执行 D-A,第 25-50s 执行 D-B,第 50-60s 留空观察;轮间不重置浏览器(保留 cookie/缓存现实性)。
  2. 时序对齐:本机与设备对时;服务器日志本身带时间戳,设备动作记录到秒(截屏带时间水印或手记)。
  3. 结果编码:每轮每形态记 通/拦;同时记录策略拉取周期参考点(设备端日志 00:01 周期 + 手动触发拉取周期,见文档附录时间线)。
  4. 收敛规则:
    • 5/5 一致 → 判定「确定性」,采纳该形态结论;
    • 出现 ≥1 次翻转 → 判定「存在同步窗口/非确定因素」,追加 2 轮并定位翻转是否贴合策略拉取时刻;
    • 全程全拦且与体积无关 → 支持基线回滚后现状(9-7 基线轻量版),历史「全通」归因于当时内联注入形态或同步窗口。
  5. 对照组:同轮次内,137 热点下同页面应全通——用于排除服务端故障假象。

8防御侧配对(Detection Pairing)

对每一条「可能被放行的形态」,给出防御侧应做的检测信号与修复动作——这是本演习对部署 owner 与厂商的双重产出。

可放行形态本地/管理端检测信号引擎修复建议(厂商)管理端止损
B1 字符串匹配(userinfo / query / 任意位置域名)URL 中出现 @ 的导航即告警;命中「白名单域名但解析 host 为 IP」模式改为解析后 host 精确匹配;userinfo 一律拒绝或剥离后再判定加入「禁止 userinfo 导航」策略项;相关域名串事件上报表
B2 子资源逐请求字符串判定日志聚合:同一页面出现「域名串 + IP host」子资源突发判定点统一到解析后 host+port 规范形对含 @ 的资源请求降级拦截并记录
B4 明文 WS/热点放行非白名单目标建立 TCP 的周期审计;137 网段流量旁路识别WS 握手纳入同规则;端口归一(80/443/自定义)课堂热点纳入策略覆盖或物理隔离(文档 §十四 残余风险)
B5 同步窗口策略生效时差监控:拉取时刻前后 1-2 分钟加强审计策略原子生效 + 版本生效时间戳上报关键时段(课堂)缩窗口;生效前保持上一策略
CIDR 条目无效定期「条目-引擎」一致性巡检(脚本比对清单与实测)实现 CIDR 解析引擎或移除误导性条目管理端 UI 明示「网段条目需引擎支持」
最终处置建议(非入侵路径):CI 正式访问的正道仍是管理端将自有域名入单(文档 §六),本演习证据用于驱动该工单与厂商修复,而非绕过长期运行。
